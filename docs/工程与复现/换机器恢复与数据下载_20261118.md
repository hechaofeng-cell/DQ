# 换机器恢复与数据下载

更新：2026-11-18。适用范围是当前六分类主线、最新 Objects365 新图片实验，以及已保存的历史池成员。GitHub 提供代码、文档和精确数据清单；公开源图片在新机器重新下载。原机器上的数据和冻结文件没有被移动或改写。

## 1. 先决定恢复哪一层

| 目标 | 所需材料 | 是否需要下载图片/权重 |
| --- | --- | --- |
| 复算 2026-10-18 的冻结统计结果 | 仓库内便携 ZIP、Python 3.12、包内 NumPy | 不需要；见[统计复算说明](../实验方案与结果/latest_coverage_reanalysis_20261018.md) |
| 恢复最新实验的精确原图与成员 | 本文的清单及恢复工具 | 从 18 个源包提取 5400 张候选原图；入选名单固定为 4800 张 |
| 继续使用原来的训练模型、标注和断点 | 精确原图，加原机的权重/标注/断点备份 | 15 份训练权重不能用公开预训练模型替代 |
| 从零重做训练、标注和资格审计 | 全部相关数据、依赖、模型服务和历史排重材料 | 是另一轮执行；目前不是 clone 后一条命令就能完成 |

不要重新随机抽样代替冻结名单。4800 个正式目标中有 21 个按技术规则替换的成员，不能只取最初计划的前 4800 张。

## 2. 新机器：下载仓库并验证迁移清单

以下以 Linux、Python 3.12 为例。`git clone` 时目录名可以更改；恢复工具根据当前代码位置定位仓库，不要求存在 `/home/hcf`。

```bash
git clone https://github.com/hechaofeng-cell/DQ.git QE
cd QE
python3 scripts/restore_qe_data.py verify-bundle
python3 scripts/restore_qe_data.py plan
```

`verify-bundle` 校验迁移包内清单和历史快照；`plan` 只列出下载地址、包大小和成员数量，均不联网。恢复工具仅依赖 Python 标准库，无须先安装 PyTorch 或启动模型服务。

机器可读入口在 [reproducibility/migration_20261118](../../reproducibility/migration_20261118/)：

| 文件 | 内容 |
| --- | --- |
| `objects365_fresh_downloads.json` | 18 个包的精确 URL、字节数、整包 SHA256；5400 个原图的名称、大小、SHA256、目标相对路径 |
| `manifests/artifacts/fresh_image_qualification_20261112/qualified_manifest.csv` | 最终 4800 个目标的类别、角色、框、来源与图像/视图哈希；路径已转成项目相对路径 |
| `data_sources.json` | COCO、Open Images、VOC2007/2012、Objects365 各自的数据来源、历史成员清单和现有代码入口 |
| `trained_checkpoints.json` | 5 种架构 × 3 个训练种子的 15 份权重：相对路径、大小、SHA256 |
| `training_crops.json` | 历史训练/验证裁剪和原 YOLO 格式标签包的精确文件绑定 |
| `models.json` | 本地/在线 VLM 标识、原本地模型 digest、公开预训练骨干名称、去重编码器下载地址及 SHA256 |
| `snapshots/` | 69 份原始协议、名单、字典、提示模板、包审计及来源记录，保留原文件字节 |
| `transfer_paths.txt` | 原机器上需要另行迁移的训练输入、权重、最新主标注及失败补测记录的路径清单 |
| `provenance.json`、`manifest.sha256.json` | 文件来源、范围边界和迁移包内容校验 |

`snapshots/` 中的旧绝对路径仅作来源记录；不要把它们当成新机器已经存在的文件。迁移包刻意不包含图片像素、模型权重、API 密钥或原始服务返回。

## 3. 恢复最新 Objects365 原图

先检查是否已经有完整图片，缺失时返回非零退出码并列出路径：

```bash
python3 scripts/restore_qe_data.py check
```

在确认本机需要下载后执行：

```bash
python3 scripts/restore_qe_data.py download
python3 scripts/restore_qe_data.py check
```

默认写入当前仓库的 `artifacts/fresh_image_qualification_20261112/images/`。这些大文件继续被 Git 忽略，不会再次上传。

完整读取 18 个压缩源包合计约 **114.14 GiB 网络载荷**，只保存约 **1.01 GiB 的 5400 张原图**，不保留全部归档或下载分块。实际网络传输还取决于重试和服务端情况；工具按包顺序读取，要求为当前包图片以外至少留 20 GiB 空闲空间。后续裁剪、模型、缓存需要额外磁盘。

工具校验逐图大小/SHA256、完整 gzip 结束/CRC、整包大小/SHA256。只在完整包校验通过后生成本次来源审计，保存在独立的 `artifacts/migration_restore_20261118/source_audits/`；已有历史审计不被覆盖。已经匹配全部逐图哈希的包会跳过下载。已有同名文件若内容不匹配会停止，不会自动覆盖。

可以先下载单包，或使用已有归档：

```bash
python3 scripts/restore_qe_data.py download --package v1/patch0
python3 scripts/restore_qe_data.py download --archive-dir /mnt/objects365_archives
```

`--archive-dir` 中归档按清单命名，如 `v1_patch0.tar.gz`、`v2_patch29.tar.gz`。未指定时，还会复用项目历史 `artifacts/objects365_independent_confirmation_20261005/data/packages/` 下同名归档。不存在的包才从网络读取。

这是**逐包重试**，不是网络字节级断点续传。中断后可重跑同一命令；已通过逐图哈希的文件会复用，但缺图所在包可能需要重新读取整个压缩流。下载链接来自历史成功的来源记录，本轮没有重新传输 114 GiB 验证远端当前可用性；若来源改变，工具会报告请求或哈希错误，而不是更换样本。

若只希望把图片放到单独磁盘，可指定完整的新 QE 数据根，例如 `--root /mnt/QE`；文件按原项目相对路径写入。不要误把 `/mnt/QE/artifacts/.../images` 本身作为 `--root`。

## 4. 生成适合新路径的运行清单

```bash
python3 scripts/restore_qe_data.py localize \
  --output artifacts/migration_restore_20261118/localized_manifests
```

此目录必须尚不存在。命令为 7 份主要成员表生成当前机器的绝对路径副本，并记录原/新清单哈希；也支持 `--root /mnt/QE`。

这一步只转换路径，**不会**重新生成裁剪/标记图、补齐 API 调用记录、改写原冻结清单或证明历史排重审计在新机重做成功。生成的清单仍保留原图及视图哈希，缺少的视图需要按原框和原渲染实现生成，并校验相应哈希；不能把原图直接当裁剪图使用。

旧执行脚本有些仍硬编码旧路径、验证历史文件哈希，不能把本地化副本直接覆盖回历史名单来“绕过”冻结检查。继续最新全量流水线前，应为新路径建立单独的执行版本，先核对成员、框、原图和视图哈希，再做小规模检查。源图恢复通过不代表全实验恢复完成。

## 5. 其他数据集应该下载什么

精确源记录见 `data_sources.json`，成员见 `manifests/`，不要仅凭目录名称下载一个“相近版本”。

| 数据 | 已固定的范围 | 获取与检查方法 |
| --- | --- | --- |
| 历史 COCO B 池 | 2400 个目标；名单含 `image_id`、`source_split`、框及图像哈希 | 按 `http://images.cocodataset.org/{source_split}/{image_id}.jpg` 获取对应图片；保留 12 位编号 |
| 历史混合 A 池 | 2400 个目标，包含 Open Images 的 train/validation/test，另含 111 个 VOC2012 羊目标 | Open Images 按 split 和 ID 下载；VOC2012 行从指定年份归档取图，不能套用 Open Images URL |
| VOC2007 C 池 | 600 个目标 | 下载 trainval 与 test 两份归档；现有 `scripts/download_sixclass_voc_sources.py` 含 URL、大小和 MD5，快照另保留 SHA256 |
| 历史 Objects365 D 池 | 2400 个目标 | 按该池自己的 `source_file_name` 和来源审计获取；与最新 4800 张是不同池 |
| 分类器训练/验证 | 1800 个训练目标、390 个验证目标 | 保存精确成员与裁剪哈希。公开 COCO 原图可重新获取，但部分旧行没有完整裁剪几何；为保留原训练输入，应迁移对应裁剪 |

本次新增的 `restore_qe_data.py download` **只自动恢复最新 5400 张 Objects365 候选原图**；其他来源已登记精确成员、来源和历史处理入口，尚未统一接入该下载命令。旧脚本的抽样/全流程入口可能生成新名单，不应直接重跑来替代冻结名单。

原项目 `data/coco2017/coco2017labels.zip` 是旧代码读取的 YOLO 格式标签包，不能用官方 COCO JSON 标注 ZIP 直接顶替。它的大小/哈希已记录，并加入另行迁移清单。

## 6. 哪些材料需要从原机器迁移

15 份已训练权重合计约 **5.73 GiB**，它们是你的实验产物，没有公开下载地址。重新下载公开骨干后重训不保证与原权重完全相同。训练/验证裁剪、原标签包、已获得的自动标注和断点也应单独保留。

若要保存当前这条主线的这些材料，在原机器的 QE 根目录执行以下命令。它只创建备份，不删除源文件；目标目录应选择有足够空间的外部位置：

```bash
tar -czf /mnt/backup/QE_private_state_20261118.tar.gz \
  --verbatim-files-from \
  --files-from=reproducibility/migration_20261118/transfer_paths.txt
```

`transfer_paths.txt` 覆盖 15 权重、当前训练/验证裁剪、原标签 ZIP、最新全量 A/B 标注目录及失败补测目录。它不是整个 `artifacts/` 的备份，也不保证包含所有历史实验、全部缓存或模型 C 的额外补充文件。若需要所有实验的原始记录，应另行保留相应产物目录。

新机器恢复前先检查压缩包成员，再解压到新的 QE 根目录；不要直接覆盖有修改的旧目录。迁移后核对：

```bash
python3 scripts/restore_qe_data.py check --checkpoints --training-crops
```

该命令核对最新原图、15 权重、训练/验证裁剪和原标签 ZIP。主标注/断点目录尚不在这个检查命令的逐文件审计范围，仍需按其原始代码/输入冻结记录核对。在线服务配置和密钥不在备份列表中，应由你单独安全配置。

## 7. 环境与模型

- 下载和文件校验工具：Python 标准库即可；本机用于工程验证的是 Python 3.12。
- 图片处理/统计：按相应流程安装 Pillow、NumPy、SciPy、requests、ijson、jsonschema 等；统计便携包使用其自身依赖表。
- 分类器训练/推理：根据新 GPU 和驱动安装兼容的 PyTorch/torchvision；现代五架构还涉及 transformers、timm、ultralytics、open_clip 及 Perception Encoder 实现。仓库现有 `requirements-dta.txt` 并不是全工程统一锁文件。
- 本地 A：`qwen3-vl:30b-a3b-instruct`。原 digest 在 `models.json`；`ollama pull qwen3-vl:30b-a3b-instruct` 能拉取该名称，但名称相同不保证未来 digest 相同，迁移后应比对记录。
- 在线 B：`sensenova-6.8-flash-lite`。恢复可用的 URL/model/请求参数配置，并单独设置 `SENSENOVA_API_KEY`。原入口读取 `artifacts/feature_pilot_20260908/api_config.local.json`；此文件未上传，只有密钥环境变量并不足以替代其余配置。
- 去重编码器：`torchvision ViT_B_16_Weights.IMAGENET1K_V1` 的来源和 SHA256 已记录。它不是目标分类器；公开预训练权重也不是你的 15 份微调权重。

本次不会为你重新下载大数据、重训或重新发起 VLM 调用。这里补齐的是可检查的数据来源、精确成员、下载恢复工具和迁移步骤，不宣称所有历史实验已经可在任意机器一键重跑。
