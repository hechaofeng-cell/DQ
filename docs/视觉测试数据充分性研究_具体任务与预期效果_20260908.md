> 日期：2026-09-08。依据：约 29 分 46 秒的录音、手绘图、所附科研创新分析，以及当前 QE 项目的相关文件。

> 本文把材料中的讨论转化为可执行的任务说明。录音采用本地自动转写，时间段用于回查，内容以概括为主，不作为逐字引语；口音、背景声和专业术语存在识别误差。已对关键段落做两轮自动转写交叉核对，第二轮部分片段出现漏词和提示词重复，未据此补造内容。手写不清的文字不强行辨认。材料中的操作建议是被分析的内容，不等于本次要求执行全部实验；本次交付为任务分析文档。

## 1. 先给结论：这项工作到底让你做什么

**你需要做一套“基于可解释视觉特征的测试数据覆盖分析方法”：把一批图片转成有规则的特征标签，统计这些特征及其变化覆盖了哪些情况、缺少哪些情况，最终用实验验证这些诊断是否有助于改进测试集。**

以犬类图片为例，输入一批照片，系统应能回答：

- 主要对象是谁？每张图标注的是哪一只犬？
- 头部朝向、嘴部开合、眼部可见性等特征，分别有哪些状态？
- 整批图片里，各状态有多少张、占多少比例？哪些无法判断？
- 是否几乎都是正面、清楚、无遮挡的图片？侧面或遮挡等指定场景是否缺失？
- 根据已经说明的测试目标，应该补充哪些类型的图片？
- 补充之后，能否覆盖原来缺少的场景，并在同等预算下获得更有用的测试证据？

**近期最应该完成的是一个可信的小实验：特征规则 → 大模型标注 → 人工核验 → 分布统计 → 人为缺口对照。** 完整的充分性公式、跨类别推广和模型故障检出实验，是在这个基础上的后续工作。

录音没有给出完整算法和正式验收阈值。它提出了方向，也把“特征如何定义”“变化如何量化”“参照分布如何确定”留给你研究。这些正是你需要补齐的内容。

### 2.2 手绘图：把上述过程画了出来

图中能辨认出对象示意、眼/鼻/口等标记、多条分布曲线、箭头以及 0—1 的刻度示意。结合录音，较合理的解读是：

```mermaid
flowchart LR
    A[一批待评价图片] --> B[确定对象及特征模板]
    B --> C[逐图标注特征状态]
    C --> D[按特征统计分布]
    D --> E[依据目标诊断覆盖缺口]
    E --> F[补样并验证变化]
```

其中有三点不能从图上直接推定：

1. 曲线画成钟形，不代表真实特征必须服从正态分布。
2. 图上的 0—1 可能表示某个特征的变化程度，不代表已定义了整套测试集的充分性总分。
3. 某个区域样本少，不自动说明不充分；还要知道该区域是否属于目标任务，以及应该有多少证据。

手绘中的人脸是解释对象拆解的例子，录音还举了鸟、车、手写数字等例子。**没有足够依据把研究限定为人脸，也没有要求第一轮同时处理所有类别。**

### 2.3 附件 Markdown：更大的研究框架

附件将目标概括为 Distribution-based Test Adequacy（DTA），讨论统计、几何、语义、边界、长尾等维度，以及充分性与缺陷暴露能力之间的验证。

它适合用来理解研究背景和最终目标，但不能把其中每个维度、每个数据集、每个理论设想都当作近期必须完成的工作。附件自己也出现“五维总体框架”和“黑盒版三维、可选扩展”的范围差别。

**综合排序：录音和手绘图决定近期切入点；附件提供长期框架；具体方法是否成立，由实际实验决定。** 这是一种需求解释，并非断言录音已给出了完整、无歧义的技术规格。

## 3. 必须先分清的四个概念

| 概念 | 评价谁 | 回答的问题 | 在本项目中的位置 |
| --- | --- | --- | --- |
| 特征状态/程度 | 单张图片的某个特征 | 嘴是张开还是闭合？头是正面还是侧面？ | 形成可统计的数据 |
| 图片识别难度 | 单张图片相对于特定模型或模型群 | 模型识别它有多困难？ | 可作后续辅助分析 |
| 测试数据覆盖/充分性 | 整批图片，相对于明确目标 | 该测到的条件是否有代表？证据是否够？ | 本次研究的核心 |
| 模型测试表现 | 被测模型 | 在给定图片上错了多少？错在哪里？ | 用于验证覆盖诊断的价值 |

例如，嘴部开合程度为 0.8，只描述一个特征，不能直接解释为图片难度 0.8，更不能解释为测试集充分性 80%。同样，很多模型都能识别一批图片，也不意味着这批图片覆盖了所有重要场景。

录音中以“正常—变化较大”解释特征变化，可以帮助构思分级；实际规则应改写为可观察的属性，避免依靠“正常”“漂亮”“典型”等含糊判断。把一切常见状态赋高分，还可能掩盖测试中需要保留的少见状态。

## 4. 你具体需要完成的七项工作

### 工作一：写清研究对象和第一轮边界

第一轮建议沿用已经准备好的犬类图片，以一个明确任务验证流程。任务定义至少写清：对象类别、图片来源、主要对象选择规则、拟覆盖的视觉条件和允许的模型访问方式。

建议的一句话定义是：

> 针对犬类测试图片，利用冻结的可解释特征规则和外部视觉大模型进行逐图标注，评价指定视觉状态的覆盖情况，并验证其缺口诊断是否可靠。

**交付物：一页任务定义。完成效果：别人能清楚判断一张图片是否在范围内，以及本轮分析回答什么问题。**

需要注意，外部标注模型与被测分类模型承担不同职责。前者提供待核验的特征标签；后者用于后续评估测试效果。使用外部模型并不意味着标签天然正确，也不意味着表示方式完全中立。

### 工作二：建立“通用模板 + 类别实例”

通用性体现在字段结构和规则制定过程，不要求所有类别都具有同一组部件。

| 模板层级 | 要记录的内容 | 犬类示例 |
| --- | --- | --- |
| 对象 | 分析什么；多对象时选谁 | 选可见身体投影面积最大的犬，并有平局规则 |
| 部件或属性 | 观察什么 | 头部朝向、嘴部开合、眼部可见性 |
| 状态 | 允许输出什么值 | 正面、斜向、侧面、背向、无法判断 |
| 判据 | 如何根据原图决定状态 | 依据鼻口方向和可见面部结构判断头部朝向 |
| 异常与不确定性 | 看不清、找不到对象、多个目标不明确怎么办 | absent、ambiguous、unknown 分别记录 |
| 可见证据 | 如何复核 | 目标位置及支持判断的局部线索 |
| 版本 | 使用哪套规则 | 规则版本、提示词版本、变更原因 |

第一轮选择少量可稳定判断的特征即可。当前项目已有头部朝向、嘴部状态、眼部可见性三项，可以继续核验；鼻部形态、耳部朝向、身体姿态等作为候选扩展，不能因为录音举了例子就全部加入。

大模型可以建议特征和状态，但你需要检查：是否能从图片观察、是否与识别任务有关、不同状态是否容易混淆、是否存在不可能的组合。

**交付物：特征字典、固定提示词、带说明的正反例。完成效果：不同标注者使用同一规则时，能理解同一个标签的意思。**

### 工作三：把每张图片转成结构化记录

每张图至少保留：图片 ID、文件哈希、对象状态、每个特征标签、可见依据、模型及规则版本。多对象图片必须能复核标注的是同一个对象。

输出示意如下，内容为格式说明，非真实实验结果：

```csv
image_id,target_status,head_view,mouth,eyes_visible,evidence
example_001,present,side,open,one,画面中央目标犬为侧脸且可见张口与一侧眼部
example_002,present,unknown,unknown,unknown,目标头部过小且模糊
```

第一轮优先采用离散标签。连续值只有在定义好端点、测量依据和误差容忍度后才值得加入。例如用 0—1 表示嘴部开合程度，需要解释 0、1 和中间值究竟对应什么，不宜只让模型凭感觉给小数。

**交付物：逐图标签表、原始回复、异常记录。完成效果：每个汇总数字都能追到具体图片和原始标签。**

### 工作四：证明大模型的标注值得使用

这一步是录音强调的“用数据证明大模型做这件事是否靠谱”。需要分别检查两个问题：提出的特征规则是否合适，按规则识别具体图片是否准确。

建议实施以下核验：

1. 在练习图片上修改歧义规则，记录修改原因。
2. 固定规则后，你先独立标注验证图片，不先看模型答案。
3. 对同一验证图片运行两遍独立模型标注，保持模型、提示词和可见设置一致。
4. 逐字段比较人工参考、模型第一遍和第二遍；对分歧回到原图复核。
5. 报告每种状态的样本数、混淆和 unknown，避免只报一个平均准确率。

若具备人力，增加第二位独立人工标注者并裁决分歧，会比把一个人的判断直接当作绝对真值更有说服力。第一轮人数有限时，明确标注“单人参考”。

建议至少输出：

- **与人工参考的一致情况**：每个字段答对数/人工可判数；人工可判而模型 unknown 的情况单独列出，并计入未答对。
- **重复稳定性**：相同图片两次标注是否一致；共同 unknown 单列，不能靠共同无法判断取得好看的稳定性。
- **分布偏差**：在同一批可比较图片上，模型状态计数与人工状态计数相差多少。
- **规则问题**：分歧源于目标选择、标签定义、图片本身，还是模型识别错误。

**交付物：逐字段核验表、分歧图片清单、规则问题清单。完成效果：知道哪些字段可以进入覆盖统计，哪些只能作为探索性输出。**

仅验证“返回了合法 CSV”不能替代这一步。高一致率也需要看类别分布：如果几乎都是闭嘴，始终预测闭嘴也可能取得好看的平均值。

### 工作五：统计分布，并明确“缺口”是相对什么而言

这一项需要分三层推进。

**第一层：描述当前数据。** 输出每个特征各状态的数量、比例和无法判断比例。例如“没有检测到侧面图片”“嘴部无法判断比例较高”。如果没有参照，只能得出这样的描述。

**第二层：检查预先规定的覆盖要求。** 例如本轮任务明确要求包含正面、斜向、侧面和背向，那么其中某种状态没有可核验图片，就形成“相对于这份清单的覆盖缺口”。该清单和最低证据量需要提前说明。

**第三层：比较目标参照分布。** 当有来自目标使用条件的独立参考图片，才能进一步判断当前比例与参照有多大差异。公共图片库可用作研究代理，但不能未经说明就当作真实部署分布。

一个基础统计定义可以是：设目标有效图片集合为 T，特征 f 的标签为 y_f(x)，则状态 s 的计数为

\[
n_{f,s}=\sum_{x\in T}\mathbf{1}[y_f(x)=s],\qquad p_{f,s}=n_{f,s}/|T|.
\]

unknown 作为独立状态保留；对象不在范围内的图片单独报告。若只对可判图片计算比例，必须另列分母和被排除的数量。

如果预先定义了该特征应覆盖的有效状态集合 S_f 和最低独立样本数 k_{f,s}，可计算一个简单的清单覆盖量：

\[
C_f=\frac{\sum_{s\in S_f}\mathbf{1}[n_{f,s}\ge k_{f,s}]}{|S_f|}.
\]

这是**本报告建议的入门定义，不是录音给出的公式，也不是已验证的充分性标准**。k=1 只表示“出现过”；并不能说明足以评估模型在该状态上的表现。复制图片不应被当成新增独立证据。

单特征都覆盖，也可能缺少组合。例如既有侧脸也有张嘴，不代表有“侧脸且张嘴”。后续可检查有任务意义、实际可行的两两组合，不应盲目要求所有特征取值的笛卡尔积全部出现。

**交付物：特征分布表、覆盖矩阵、缺口证据、参照说明。完成效果：能清楚指出“哪一种条件缺了或证据少，以及为什么认为它需要被覆盖”。**

### 工作六：做一个主动制造缺口的对照实验

自然数据里有没有缺口，有时很难判断。一个更容易检验流程的方法是：人为构造已知缺口，再看系统能否发现。

建议使用“侧面头部”作为现有流程的首个例子：

1. 依据人工参考标签，构造包含侧面图片的集合 A。
2. 构造不含侧面的集合 B，用其他不同图片补齐，使 A、B 总张数相同。
3. 用相同的标注规则分别统计 A、B。
4. 检查系统是否发现 B 的侧面缺失，并定位到正确特征。
5. 从独立候选图片中补入侧面图片，检查相应覆盖是否变化。

A 只是包含指定状态的对照集，不代表它已充分。不同特征可能随选样一起变化，因此第一轮应报告其他特征变化；后续扩大数据后再尽可能配平。如果没有足够侧面图或替补图，应报告条件不足，不能复制图片凑结果。

**交付物：A/B 图片清单、等规模说明、缺口前后统计、错误诊断样例。完成效果：证明流程至少能感知一个人为已知缺口。**

这一步还没有证明“因此能发现更多模型错误”；它只验证缺口诊断这一环。

### 工作七：进一步验证诊断是否改善测试

当规则和缺口诊断通过初步核验，再接入被测分类模型。

从同一个初始测试集、同一个候选池出发，在相同新增图片预算下比较：随机补样、按特征状态分层补样、按本方法诊断补样。标签核验和模型访问条件应一致。

至少分别报告：

- 覆盖了多少原先缺少的有效条件；
- 新发现多少有可靠标签支持的错误图片；
- 若声称发现不同故障类型，类型如何定义、合并和去重；
- 标注成本、模型调用成本和不确定性；
- 在未参与规则调整的模型或数据上的效果。

原始错误图片数与独立故障类型数不是同一个量，不能把同一问题产生的近重复错误全部算成不同缺陷。只提高自己的覆盖分数也不构成独立的应用收益证据。

**交付物：等预算对照实验及完整记录。完成效果：判断这套方法是否比简单方案更值得用。** 结果可能支持、部分支持或不支持预期；出现负结果应修正规则或收窄主张，不必为了凑结论不断增加指标。

## 5. 做完之后应该看到什么效果

应分开验收三个层次，不能用后一个目标倒推前一个已经完成。

| 层次 | 应看到的具体效果 | 验收证据 | 当前能否宣称达到 |
| --- | --- | --- | --- |
| 流程跑通 | 输入图片后自动生成标签、计数和报告，异常可追溯 | 原图清单、原始回复、逐图表、运行记录 | 现有六张练习图已部分证明 |
| 方法初步有效 | 标注与人工参考相符且有稳定性，能识别人为缺口 | 独立核验、重复标注、A/B 对照和分歧分析 | 尚缺完整证据 |
| 具有研究和应用价值 | 对真实任务的缺口诊断有用，等预算改善测试，并能说明比已有方法多了什么 | 强基线、独立数据/模型验证、成本与误差分析 | 尚未验证 |

一个合格的最终报告，应该让使用者直接看到下面这些内容。以下为**输出结构示意，不是当前数据的实测结论**：

| 报告栏位 | 示例说明 |
| --- | --- |
| 数据范围 | 哪一批犬类图片，什么来源，什么任务 |
| 标签可信程度 | 哪些特征完成核验，哪些仍有歧义 |
| 分布现状 | 每种朝向、嘴部状态和眼部状态的数量 |
| 明确缺口 | 测试清单要求的某种状态未出现 |
| 证据不足 | 状态出现过，但独立样本太少或标签大量 unknown |
| 建议动作 | 收集或复核哪些图片，解决哪个具体缺口 |
| 改善效果 | 等预算补样后改善了哪些覆盖和测试结果 |
| 适用边界 | 仅对哪些对象、特征规则和参考分布有效 |

### 5.1 不应现在写死一个“90 分及格”

材料没有给出经过验证的统一阈值。样本规模、状态难度、人工分歧和实际用途都影响可接受误差，因此不宜把任意 90%、95% 或 0.8 写成老师要求。

第一轮以“证据完整、问题可诊断”验收：记录逐项一致的分子分母，解释混淆和 unknown，说明能否感知预设缺口。准备扩大使用时，再根据该任务可容忍的标注误差、漏检代价和数据量设定门槛，并在独立数据上检查。

### 5.2 “分布充分”不等于“模型安全”

即使每个要求的特征状态都有样本，仍不能推出所有组合、所有未知环境和所有模型行为都覆盖。充分性应始终写成“相对于某个任务、某套特征、某个参照和某种证据要求的充分性”。

同样，分布贴近真实使用情况与故障检出数量不是必然同向。若专门增加少见但重要场景，测试集可能偏离自然比例，却更适合查错。报告应区分“代表性评价”和“关键条件测试”，避免合成一个意义不清的总分。

## 7. 建议的执行顺序和每次汇报内容

以下为建议安排，不是材料中已经确定的工期或人员分工。采用完成门槛推进，比强行保证几天得到研究结论更可靠。

| 顺序 | 你具体做什么 | 本阶段带去汇报什么 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| 1 | 写一页研究问题，整理通用模板和犬类实例，复核练习图 | 流程图、特征规则、几张歧义例图 | 目标和标签含义说得清 |
| 2 | 固定规则，独立填写现有验证图片的人工表 | 人工参考表、不确定和争议样例 | 参考完成且可回查 |
| 3 | 运行两遍独立标注并逐项比较 | 一致性表、状态混淆、错误图片 | 可判断哪些特征可用，问题有处理结论 |
| 4 | 输出分布，做等规模人为缺口实验 | 分布表、A/B 清单、缺口定位与失败案例 | 已知缺口的感知能力可评价 |
| 5 | 定义目标参照与证据要求，扩展数据或第二类别 | 参照说明、规则迁移问题、补样建议 | 有依据谈“相对充分” |
| 6 | 做等预算测试收益和方法比较 | 与随机/分层等基线的对照、成本、局限 | 有证据判断研究主张是否成立 |

如果近期只安排一到两个工作日，合理目标是完成规则整理、练习复核并尽量推进人工参考，交付“已做部分 + 发现的问题 + 下一步验证方案”。是否能在这段时间完成完整验证，取决于人工标注与 API 限流情况。已有记录发生过限流，因此不宜承诺固定调用完成时间。

你可以用下面这段话汇报自己的理解：

> 我理解当前先做对象可解释特征的测试覆盖。先用一类对象建立特征和变化状态规则，再让大模型逐图标注，做人工核验和重复标注，然后统计分布，用等规模的人为缺口对照检查是否能发现缺失状态。等这条流程可靠后，再确定参照分布、充分性指标和补样后的模型测试收益。近期先交付规则、逐图记录、核验结果和缺口实验，不把小样本统计直接称为正式充分性结论。

## 8. 原材料中需要修正或保留为假设的说法

这些问题影响论文表述，但不妨碍先开展上述小实验。

| 材料中的说法或倾向 | 本文建议的处理 |
| --- | --- |
| 模型输出概率，因此没有正确答案 | 对有可靠标签的分类任务，仍可按固定决策规则判对错。把动机改为标签获取、语义歧义和开放环境等实际困难 |
| 黑盒就不能看模型输出 | 区分“能否访问内部结构”与“是否依赖被测模型”。本研究核心标注和数据评分可不使用被测模型输出，后续验证可以使用 |
| 几何就是嵌入空间距离 | 录音当前切入点更接近可解释部件及外观状态；应先统一术语，再选择实现 |
| 正常图片的分数越高，测试集就越好 | 明确单图特征程度、识别难度、集合覆盖之间的差别，保留少见但有效的状态 |
| 分布应该长得像正态曲线 | 手绘是示意；先观察实际状态计数，不预设分布形状 |
| 有大模型就可以自动得到正确特征及标签 | 把规则合理性、逐图准确性和稳定性分开验证 |
| 大规模数据或模型高准确率能直接定义标准 O | 数据量大不能代替代表性说明；模型高分不能独立证明参照合适 |
| 有覆盖公式就有模型安全或泛化保证 | 当前公式只描述指定空间/清单中的覆盖；其他保证需要额外假设和证据 |
| 多维测试数据质量和充分性—故障检出验证是空白 | 已有直接相关研究，不能仅凭框架名称宣称首创 |

关于最后一项，本次核查了两篇一手摘要：Mani 等已从测试视角提出多维数据质量及引导生成；TEASMA 已研究借助充分性指标预测测试集故障检出能力。这些事实足以约束绝对“空白”的说法，但不构成对当前细分方法的完整查新结论。[Dataset Characterization，2019](https://arxiv.org/abs/1911.07309)；[TEASMA，2024 修订版](https://arxiv.org/abs/2308.01311)。

可作为后续研究假设的是：**可解释部件状态的规范化提取，是否能带来更可靠、可回查的缺口定位，并指导有效补样？** 大模型提出更多特征，本身不等于贡献；需要看这些特征是否正确、是否提供额外决策信息，以及是否优于简单的人工特征表和分层统计。

## 9. 真正需要你作出选择的地方

可以先按当前犬类小实验推进；下面这些问题需要在扩大实验前，与指导方对齐并写入方案，本文不替其虚构答案。

1. **研究任务是什么？** 是类别识别的测试数据质量，还是身份识别、检测等其他任务？当前建议按已有犬类分类数据试验。
2. **近期交付期待是什么？** 是特征提取可行性验证，还是已经需要完整的充分性评分？从录音看前者优先。
3. **“几何特征”如何命名和划界？** 是否接受部件、外观、朝向、可见性等统一作为可解释视觉特征？
4. **什么条件必须覆盖？** 来源是场景需求、专家清单、独立采集的参考分布，还是暂用公共数据代理？
5. **最终优化什么？** 代表真实使用情况、发现更多错误，还是在预算下覆盖指定关键条件？不同目标可能要求不同选样策略。
6. **何时扩展？** 先完成一个类别的可信核验，再做跨类别模板；具体类别数和样本量根据首轮发现决定。
