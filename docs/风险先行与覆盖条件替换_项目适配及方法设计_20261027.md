# 风险先行与覆盖条件替换：项目适配及方法设计

日期：2026-10-27  
状态：方法设计与流程图修订；尚未实现或验证条件替换算法。

## 1. 核心思路

先按风险配额形成完整初始测试集，再检查视觉状态覆盖。达到预先设定的覆盖基线，就固定集合并开展模型评价；只有未达标时，才在原风险配额内替换目标，重新检查，直至达标或满足停止条件。

风险负责约束测试集的构成，覆盖负责检查测试证据是否充分，并在必要时指导调整。视觉状态和覆盖编码可以提前计算；计算覆盖指标本身不触发换图。这里的“换图片”具体指替换以目标框确定的目标实例，不修改图片内容或目标标签。

## 2. 为什么适合当前项目

项目的问题定义是在有限预算和指定类别、视觉风险构成下，使预先界定的视觉条件得到更广泛、更充足的样本支持，并据此评价固定模型。因此，新流程与现有研究目标相符。

| 项目已有基础 | 新流程中的作用 |
| --- | --- |
| 共享与类别专属视觉状态字典、逐目标标注 | 提供风险评分与覆盖统计的统一输入 |
| 尺度、可见性、遮挡、截断、朝向五维风险评分 | 确定候选目标的风险层和风险单元 |
| 类别内 Q1–Q5 及细分风险单元配额 | 约束初始抽样及后续替换 |
| 状态编码矩阵与支持数 | 计算当前集合的出现覆盖和支持完成度 |
| 缓存预测与风险分层评价程序 | 在最终集合固定后重新计算模型指标 |

已有四类专属状态实验采用每类候选 400 个、入选 200 个、每层入选 40 个、支持上限 K=20。这些是该实验的既定配置，可作为首次验证新方案的起点，不代表所有实验都必须采用相同预算。

### 与原算法的区别

原代码从空集合开始，在配额允许的未选目标中逐个选择覆盖增益最大的目标，直到选满预算。它执行的是“逐例加入”，并没有反复替换已选图片。

新方案先按风险配额形成完整集合，再决定是否启动覆盖优化。因此，它改变了选样和停止机制；原算法的实验结果不能直接作为新方案有效性的证据。

## 3. 输入、固定条件与输出

输入包括具有类别标签和目标框的候选池、冻结的视觉状态字典及状态记录、固定风险评分与配额、测试预算，以及预先确定的覆盖阈值和停止规则。

初始抽样前固定候选池、字典、风险规则、层归属和风险单元配额。替换期间保持样本量及各单元入选数量。分类模型的预测、置信度和错误信息只用于最终评价，不参与阈值选择或换图。

输出包括最终目标集合、风险层标签、出现覆盖和支持完成度、达标状态、替换记录，以及模型分层评价结果。未达标停止时，仍保存最终集合与失败原因，单独标注其状态。

## 4. 覆盖基线如何定义

对于类别 c，令 U_c 为预先冻结的有效视觉状态字典，S_c 为该类当前已选目标集合，A_i 为目标 i 激活的状态集合。状态 s 的支持数为：

\[
n_s(S_c)=\sum_{i\in S_c}\mathbf{1}\{s\in A_i\}.
\]

同一目标对同一状态最多贡献一次支持。unknown 不作为有效状态；候选池中未出现、但已声明的状态继续保留在原有字典分母中。

### 出现覆盖率

\[
C_{\mathrm{occ},c}(S_c)=\frac{1}{|U_c|}\sum_{s\in U_c}\mathbf{1}\{n_s(S_c)\ge1\}.
\]

它回答“哪些状态至少出现过一次”。

### 支持完成度

\[
C_{\mathrm{sup},c}(S_c)=\frac{1}{|U_c|}\sum_{s\in U_c}\min\left(\frac{n_s(S_c)}{K},1\right).
\]

沿用当前实验时 K=20。它衡量各状态获得足量支持的完成程度，**不等于支持数达到 K 的状态比例**。仅靠出现覆盖可能在每个状态只有一个样本时就宣布达标，因此本版建议同时检查支持完成度。

### 建议达标条件

\[
\forall c:\quad C_{\mathrm{occ},c}\ge\alpha_c\quad\land\quad C_{\mathrm{sup},c}\ge\beta_c.
\]

建议逐类检查，避免整体平均掩盖个别类别的不足。若采用统一阈值，则所有类别共用 α、β；图中使用这一简写。具体数值尚未确定，应结合预算、独立开发设置及可达性分析预先固定，不能根据最终模型表现回调。

共享和专属状态继续分开报告。若合并字典用于达标检查，需同时保存两个子字典的指标，防止较大的状态组掩盖较小状态组的缺口。

候选池本身缺失状态时，100% 出现覆盖不可达；在给定预算及风险配额下，可达范围可能更低。候选池覆盖只能作为宽松上界，不能当成同预算最优值。未达标时应区分池内缺失、配额或预算限制，以及搜索规则未找到改进。

## 5. 初始选样与条件替换

### 初始集合

建议首先采用固定随机种子的细分风险单元内无放回抽样，按各单元配额一次性形成完整集合 S0。这样可以清楚区分初始抽样和后续覆盖优化，也能复用项目已有的同配额随机对照。

### 替换范围

对于被替换目标 x 和新目标 y，要求 x 已入选、y 尚未入选，且两者属于同一类别和同一细分风险单元。当前控制不止 Q 层，还包括风险中点及不确定性区间宽度；只保持 Q1–Q5 数量相同不足以复现原来的精确配额控制。

替换后的集合为：

\[
S'=(S\setminus\{x\})\cup\{y\}.
\]

必须先扣除 x 的贡献，再加入 y 的贡献。只计算 y 的新增状态，会遗漏移出 x 导致的状态损失。

### 接受与停止规则

可用预设基线缺口衡量调整方向，例如：

\[
D(S)=\sum_c\left[\max(\alpha_c-C_{\mathrm{occ},c},0)+\max(\beta_c-C_{\mathrm{sup},c},0)\right].
\]

作为初版实现建议，只接受 D 严格下降、且已达标指标保持达标的替换；数值容差、候选顺序和同分处理在运行前固定。该规则便于避免来回换图，但可能停在局部无法改进的集合，不保证找到全局可行解。单目标交换、批量交换或集合重建的最终搜索方案仍需在实验协议中固定。

停止条件为：所有类别均达标；没有满足接受规则的可行替换；或达到预设迭代上限。后两种情况保留最终集合，报告未达标指标与原因。若继续做模型评价，应清楚区分达标集合和未达标集合。

```text
固定字典、风险评分、细分风险配额、预算、阈值和种子
S ← 按风险配额形成完整初始集合
计算整个集合的状态支持和两项覆盖指标

当尚有类别未达标：
    若达到迭代上限：停止，标记未达标
    搜索同一细分风险单元内的替换
    根据移出与移入后的整个集合计算净收益
    若没有满足接受规则的候选：停止，标记未达标
    执行选定替换
    更新支持数并重新检查两项覆盖指标

保存集合、风险配额核验、达标状态与覆盖报告
固定集合后开展模型评价
```

## 6. 需要补充的实现与验证

已有代码可复用字典、风险分层、精确配额抽样、状态统计及评价部分。新增部分包括逐类双阈值检查、移出和移入的支持更新、条件替换搜索、接受规则、终止状态及替换日志。应核验增量支持与整集合重算一致、无重复目标、预算和精确配额保持一致，以及选样未读取分类预测。

建议在相同候选池、预算、字典和风险配额下比较：

| 方法 | 用途 |
| --- | --- |
| 同风险配额随机抽样，不调整 | 检查初始集合质量及新增调整的作用 |
| 原配额约束覆盖贪心 | 比较新方案与现有方法的覆盖和诊断表现 |
| 风险先行、未达标才替换 | 验证条件触发策略 |

记录最终两项覆盖、逐类达标率、初始集合直接达标比例、替换次数、候选评估次数、选样耗时、停止原因及模型分层指标。采用多个预先确定的初始种子，并区分选样随机性与模型训练种子。

“替换次数少”不自动等于“计算更快”：搜索替换可能需要评估大量候选，必须实际计时。最终出现更多错误或更低 F1，也不能直接解释为模型能力提高或方法普遍优越。
