# 风险约束重选与覆盖反馈迭代：修订版

本版根据用户“迭代是要去风险约束层面重新选择”的澄清，替代同日“预留名额、逐例追加”草图的流程设计。属于图形和方法设计修订，未重跑实验。

## 主流程

字典确定与自动状态提取 → 固定五维风险评分、类别内Q1—Q5分层与风险配额 → 风险约束选样 → 当前测试集覆盖评价 → 达标判断。

- 达标：固定所选测试集，输出覆盖报告，再进行多模型分层评价。
- 未达标：反馈缺失状态和低支持状态，返回**风险约束层的贪心重选模块**；在同一预算、同一配额约束下替换目标或重新组织集合，再计算覆盖。
- 无可行改进或达到预设迭代上限：保留较优集合，报告未达标情况。

反馈回路的终点是风险约束选样模块，不是状态提取、人工审查或风险评分模块。评分规则、候选池风险层归属和各层配额固定；变化的是配额内入选目标。不会因某状态覆盖不足就将其直接加到风险分数中。

## 与上一稿的实质区别

上一稿按部分初始预算选样，后续不断追加目标。本版取消该假设：首轮可按既定完整预算和风险配额形成集合；覆盖检查后回到风险约束层重选。即使预算已用满，也可通过配额内替换调整状态支持。

覆盖仍使用固定字典上的出现覆盖率与支持完成度。支持完成度为平均min(n/K,1)，当前K=20，不等于达到K例的状态比例。

重选会移除部分目标，因此必须按新集合重算全部状态支持。旧的“只追加目标使累计覆盖自然非下降”性质不再适用于跨轮重选曲线。需要事先固定改进判据和接受规则，防止反复切换；也不能仅因重新运行确定性贪心就声称会持续改进。

## 后续实现需要固定的设置

覆盖反馈如何作用于重选优先级、采用同风险单元交换还是反馈引导的集合重建、接受重选的覆盖效用、两项阈值、无改进停止规则与最大迭代次数，均须在运行实验前明确。图中“配额内替换／重选”表示设计层面的可行操作，不代表已经完成这两种实现的实验比较。

沿用项目时，仍需保持类别×风险层配额，必要时保持风险中点与未知区间宽度的细分单元配额。所有迭代不读取分类器的预测或错误，模型评价在所选集合冻结之后开展。
