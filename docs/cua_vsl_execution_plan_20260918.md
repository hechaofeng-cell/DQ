## 2. 推荐的最终实验协议

### 2.1 不重新划分基础训练集

推荐保留当前：

```text
D_train_base = 6,800
D_val        = 150
D_test       = 500
D_difficulty = 100 dog
U_dog        = 3,000 dog candidates
```

不建议从 1,500 张基础 dog 中再划出 `D_cal`，因为这会改变当前基线和覆盖分布，也可能人为拿走最稀有状态。改用分层 K 折交叉拟合，在训练集内部生成训练外预测。

### 2.2 状态效用参考模型

预注册两个参考模型：

```text
ResNet-18
ConvNeXt-Tiny
```

对 6,800 张基础训练样本进行三折分层交叉拟合：

1. 每折用 2/3 训练数据训练；
2. 预测剩余 1/3；
3. 三折合并后，每张样本都有一次训练外预测；
4. 只取 1,500 张 dog 的训练外预测；
5. 分别计算两个参考模型的状态条件错误率；
6. 对两个模型的错误率取平均，得到固定 `e_s`。

这样生成的效用信号：

- 不使用测试集；
- 不占用候选池；
- 不是模型对训练图片的记忆结果；
- 对后续四个评估骨干保持一致。

### 2.3 状态错误平滑

首先计算参考模型全部 dog 折外样本的错误率 `e_global`。对每个状态：

```text
e_s = (FN_s + beta * e_global) / (N_s + beta)
beta = 10
```

这样，小样本状态向全局 dog 错误率收缩，不会因为只有一两张图片就产生 0% 或 100% 的极端优先级。

建议同时输出：

```text
state_id
train_count
oof_support
oof_false_negative_count
resnet18_error
convnext_error
smoothed_error
coverage_deficit
joint_priority
```

### 2.4 三种补图集合

从同一 3,000 张候选池生成：

```text
random300_r0 ... random300_r4  五组独立随机集合
gap300                         纯覆盖边际增益集合
CUA300                         覆盖－效用联合边际增益集合
```

联合优先级：

```text
d_s = max(0, tau - n_s) / tau
p_s = d_s * e_s
tau = 30
```

候选图片使用动态边际增益贪心选择。每选一张就更新剩余缺口，避免连续选择重复状态。

### 2.5 测试集策略

分为两个层次：

#### 最小可执行版本

- 保持主测试集 500 不变；
- 对其中 100 张 dog 和困难测试集 100 张 dog 运行 dog_v3.1；
- 人工复核这 200 张；
- 主测试 dog 与困难 dog 分开报告状态指标，不把两个不同采样分布直接混成一个总体分数。

#### 论文增强版本

- 额外从未参与训练和候选选择的 Open Images 验证/测试来源冻结 300 张 dog；
- 只依据视觉状态进行分层构造，不使用任何分类模型测试结果；
- 运行 dog_v3.1 并人工复核；
- 作为独立 `D_state_test`，专门评价稀有状态 Recall。

建议先完成最小版本。只有状态样本数不足以支持主要结论时，再建立 300 张独立状态测试集。

### 3.2 状态编码器

读取：

- `configs/dog_feature_schema_v3_1.json`；
- 基础和候选 `results.csv`；
- 训练 manifest。

输出：

- 21 个枚举字段的整数标签与有效掩码；
- 2 个集合字段的 multi-hot 标签与有效掩码；
- 状态到索引的冻结映射；
- 每张 dog 图片的状态对集合；
- 非 dog 图片的全零状态掩码。

枚举字段使用交叉熵；集合字段：

```text
occlusion_parts
truncation_parts
```

使用 `BCEWithLogitsLoss`。`unknown` 使该字段整组失效；`none` 是有效且排他的状态。

### 3.3 多任务模型包装器

统一接口：

```text
features = backbone(image)
class_logits = class_head(features)
state_logits = state_heads(features)
```

四个骨干只负责产生共享特征：

- ResNet-18：替换 `fc` 为 Identity；
- ConvNeXt-Tiny：替换最后分类层为 Identity；
- MaxViT-T：替换最后分类层为 Identity；
- EfficientNetV2-S：替换最后分类层为 Identity。

在共享特征后新增：

- 一个五分类头；
- 21 个枚举状态头；
- 2 个多标签状态头。

推理时只读取 `class_logits`，状态头不会改变部署输出。

### 3.4 损失实现

```text
L_total = L_class + lambda_state * (L_enum + L_set)
```

要求：

- 分类损失对所有样本计算；
- 状态损失只对 dog 计算；
- `unknown` 和不适用字段不产生梯度；
- 状态损失按有效标签数量归一化；
- 状态权重与样本权重均设置上限；
- 日志分别记录 `L_class`、`L_enum`、`L_set`。

初始调参范围只使用验证集：

```text
lambda_state in {0.1, 0.3, 1.0}
alpha_sample in {0.5, 1.0, 2.0}
w_max in {2, 3}
```

选择一次后冻结，不为每个骨干单独搜索一套最优参数。

### 3.5 覆盖感知采样器

先维持当前顶层类别平衡，再在 dog 类内部调整图片概率：

```text
dog_weight_i = clip(1 + alpha * normalized_priority_i, 1, w_max)
```

每个 epoch 固定 6,800 次抽样，所有条件训练步数相同。采样日志需要保存：

- 每张图片每个 epoch 的实际暴露次数；
- 各类别抽样总数；
- 各状态预计和实际暴露次数；
- 最大、最小和分位数权重。

## 5. 分阶段执行方案

### 阶段 0：冻结协议

产出：

```text
protocol.json
frozen_split_hashes.json
state_mapping.json
research_log.md
```

必须先确定：

- 主指标：Rare-State Macro Recall；
- 安全指标：Macro-F1，避免为了稀有状态严重损害总体性能；
- 稀有状态定义：根据基础训练频数预先冻结；
- 测试状态最小支持数：建议每状态至少 5 张才进入宏平均；
- `tau=30`、`beta=10`；
- 两个效用参考模型和三折划分；
- 训练种子与随机选样种子。

### 阶段 1：交叉拟合效用估计

运行：

```text
2 个参考模型 × 3 折 = 6 次训练
```

验收条件：

- 6 次运行全部完成；
- 6,800 张训练样本每张恰好有一次折外预测；
- 没有样本由见过自身的模型预测；
- 1,500 张 dog 均能连接到 dog_v3.1 状态；
- 输出全部状态的 `N_s`、`FN_s`、`e_s` 与置信信息。

如果两个参考模型的状态错误排序相关性很低，不立即平均，应先检查：

- 状态支持数是否过小；
- 某些状态是否存在明显标签错误；
- 两个模型是否出现不同的 precision/recall 偏置。

### 阶段 2：生成补图集合

生成：

```text
5 × random300
1 × gap300
1 × CUA300
```

每张选中图片保存：

- 选择排名；
- 命中的状态；
- 选择前后剩余缺口；
- 覆盖边际增益；
- 效用加权边际增益；
- 图片哈希和目标框；
- 与其他集合的重叠关系。

验收条件：

- 每组严格 300 张真实 dog；
- 不与验证或测试集重叠；
- 没有 image ID、crop hash 或近重复；
- gap300 与 CUA300 都由冻结算法自动生成；
- 不根据后续模型结果替换图片。

### 阶段 3：状态测试集

最小版本对现有 200 张 dog 测试图片运行 dog_v3.1，并人工复核。

输出：

```text
main_test_dog_states.csv
difficulty_test_dog_states.csv
human_review.csv
state_support_report.csv
```

验收条件：

- 结构化响应全部通过或明确记录失败；
- 人工复核人不能看到模型预测；
- 状态定义与训练端相同；
- 主测试和困难测试分别报告，不混合总体比例。

### 阶段 4：多任务模型烟雾测试

按顺序执行：

1. 64 张样本上验证数据形状和掩码；
2. 小样本过拟合，确认分类损失和状态损失均能下降；
3. ResNet-18 单种子运行 2 个 epoch 的 E0、E5、E8；
4. 检查显存、NaN、采样分布和恢复逻辑；
5. 比较 E0 的新脚本与旧脚本，确保普通交叉熵基线可复现到合理误差范围。

不通过烟雾测试时不启动批量训练。

### 阶段 5：两模型先导实验

先运行：

```text
ResNet-18 + ConvNeXt-Tiny
E0-E8
3 个训练种子
共 54 次训练
```

目的不是形成最终结论，而是决定新机制是否值得扩展。

继续条件：

- E5 相比 E3 或 E4 在稀有状态指标上出现可重复正向信号；或
- E8 相比 E5 显示覆盖－效用联合机制有正向信号；
- 总体 Macro-F1 没有出现明显且一致的退化。

暂停诊断条件：

- 两个模型的状态损失都不下降；
- dog 状态头准确率接近随机；
- E5/E8 只增加 dog 误报；
- 采样权重集中在极少数图片；
- 场景状态导致明显捷径学习。

### 阶段 6：正式四模型实验

主比较先运行：

```text
E0：random300 + CE
E1：gap300 + CE
E5：gap300 + VSCAL
E8：CUA300 + CUA-VSL

4 个骨干 × 4 个条件 × 5 个种子 = 80 次训练
```

详细消融只在 ResNet-18 和 ConvNeXt-Tiny 完成：

```text
E2、E3、E4、E6、E7
2 个骨干 × 5 个新增条件 × 5 个种子 = 50 次训练
```

E5 与 E8 已在主比较中完成，不重复训练。

### 阶段 7：随机补图方差

覆盖率方面对五组 random300 全部计算，不需要训练模型。

模型方面建议先在两个代表骨干上运行：

```text
额外 4 组 random300 × 2 模型 × 3 种子 = 24 次训练
```

这一步回答当前最薄弱的问题：原来的 random300 是否只是一次偏弱或偏强的随机抽样。

### 阶段 8：报告与判定

必须输出：

- 每种子结果；
- 条件均值和标准差；
- 配对差值；
- bootstrap 区间；
- 五组随机覆盖分布；
- 主测试总体指标；
- 主测试 dog 状态指标；
- 困难测试状态指标；
- 各模块消融；
- 失败状态和代表性图片；
- 所有负结果模型。

## 6. 实验矩阵与因果解释

| 条件 | 数据集合 | dog 内采样 | 状态辅助头 | 能回答什么 |
|---|---|---|---|---|
| E0 | random300 | 普通 | 无 | 随机补图基线 |
| E1 | gap300 | 普通 | 无 | 纯缺口选样作用 |
| E2 | random300 | 普通 | 有 | 辅助头在随机数据上的作用 |
| E3 | gap300 | 普通 | 有 | 选样与辅助头组合 |
| E4 | gap300 | 覆盖 | 无 | 覆盖采样单独作用 |
| E5 | gap300 | 覆盖 | 有 | 基础 VSCAL |
| E6 | gap300 | 覆盖－效用 | 有 | 固定数据时的效用训练作用 |
| E7 | CUA300 | 覆盖 | 有 | 固定训练机制时的效用选样作用 |
| E8 | CUA300 | 覆盖－效用 | 有 | 完整 CUA-VSL |

解释规则：

```text
E5 - E3：覆盖采样贡献
E5 - E4：状态辅助头贡献
E6 - E5：效用训练贡献
E7 - E5：效用选样贡献
E8 - E6：效用选样在效用训练下的贡献
E8 - E7：效用训练在 CUA300 上的贡献
E8 - E5：完整新方法相对基础 VSCAL 的总增益
```

## 7. 指标定义

### 7.1 主指标

```text
Rare-State Macro Recall
```

定义步骤：

1. 根据 `D_train_base` 频数冻结稀有状态集合；
2. 在测试集中筛除支持数小于 5 的状态；
3. 对每个保留状态计算 dog Recall；
4. 对状态 Recall 做宏平均；
5. 同时报告每个状态的支持数，避免宏平均掩盖极小切片。

### 7.2 安全指标

- Macro-F1；
- Accuracy；
- dog Precision；
- dog F1。

Rare-State Recall 提高但 dog Precision 大幅下降时，不能判定为无条件改善。

### 7.3 次要状态指标

- Worst-State Recall；
- 遮挡 Recall；
- 截断 Recall；
- `<3%` 小目标 Recall；
- `<1%` 极小目标 Recall；
- 非典型姿态 Recall；
- 低频颜色与图案 Recall；
- 场景状态 Recall。

极小目标和极稀有状态样本数不足时只作探索性报告。

## 8. 时间与资源估算

### 8.1 已测训练速度

旧实验每个 20-epoch 运行的平均时间：

| 模型 | 单次平均时间 |
|---|---:|
| ResNet-18 | 约 1.0 分钟 |
| ConvNeXt-Tiny | 约 1.8 分钟 |
| MaxViT-T | 约 4.5 分钟 |
| EfficientNetV2-S | 约 2.9 分钟 |

旧 36 次训练顺序总计约 1.54 GPU 小时。多任务头和额外日志预计增加一定开销，因此以下时间按高于旧脚本估算。

### 8.2 新实验预计耗时

| 工作 | 预计机器时间 |
|---|---:|
| 两模型三折 OOF，6 次训练 | 约 10-20 分钟 |
| 生成 random/gap/CUA 清单 | 数分钟 |
| 现有 200 张测试 dog 的 VLM 状态提取 | 约 10-20 分钟 |
| 两模型 E0-E8、3 种子先导 | 约 1.5-2.5 GPU 小时 |
| 四模型四主条件、5 种子 | 约 4-5 GPU 小时 |
| 两模型详细消融补充 | 约 1.5-2 GPU 小时 |
| 额外随机集合模型方差 | 约 0.5-1 GPU 小时 |
| 完整训练与分析总机器时间 | 约 7-10 GPU 小时 |

如果直接运行全部 `9 条件 × 4 模型 × 5 种子`，按旧速度约 7.65 GPU 小时；加上多任务开销和多随机对照，建议预留 10-13 GPU 小时。

## 10. 决策门与停止条件

### Gate 1：数据与标签可用

通过条件：基础和候选状态能够稳定编码，抽检错误可接受，测试状态完成盲审。

未通过：先修标签和映射，不训练多任务模型。

### Gate 2：实现正确

通过条件：掩码、两类状态头、采样、公平预算和恢复机制的测试全部通过。

未通过：不启动批量实验。

### Gate 3：两模型出现机制信号

通过条件：E5 或 E8 在至少一个预注册状态指标上出现跨种子一致方向，且总体性能没有明显崩溃。

未通过：只做一次有明确诊断目的的修复实验；仍失败则不扩展四模型。

### Gate 4：正式结论

- E8 在至少 3/4 模型上优于 E5：支持跨架构 CUA-VSL 收益；
- E8 只在部分模型上提高：结论限定为架构依赖；
- E5 提高但 E8 不提高：保留基础 VSCAL，否定效用校准增益；
- 覆盖提高但 E5/E8 均不提高：保留数据覆盖诊断贡献，不声称模型改进；
- 稀有状态提高、总体指标不变：写成局部切片收益；
- Recall 提高但 Precision 明显下降：写成决策阈值或误报权衡，不写成整体改善。

## 11. 推荐执行顺序

当前最合理的顺序是：
