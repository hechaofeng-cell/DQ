# 原图难度评分协议：baseline-candidates-v1

本协议是候选评分与验证的操作协议，尚不是通过研究验收的正式分组协议。
难度表示相对于固定模型组的闭集识别难度，不表示人类感知难度、图像质量或变换后的鲁棒性。
本轮只整理、评分和验证；不生成易中难等级，不选择分组阈值，不调整样本分布，不运行蜕变测试。

## 输入与可比性

- 基准集合固定为历史 GPU 清单中 `val/val_100_per_class` 的 1,000 条原图记录，每类 100 张。
- 图像路径是 ZIP 内成员路径。`archive`、归档 SHA-256、逐图 SHA-256、原始目录路径及同源组共同确定输入。
- 类别顺序从历史 `classes.json` 与 `protocol.json` 交叉核对；本轮为十类。实现按类别列表长度处理，未把公式永久写死为十类。
- 复用 `*.jsonl.gz` 中的原始类别分数。历史字段 `logits_10` 表示本轮闭集类别分数，不是全 ImageNet 1,000 类概率。
- 同一模型权重、类别范围与顺序、预处理、评分模型组、校准参数及评分实现版本下才直接比较分数。
- `config.json` 保存权重标识、预处理文本、类别索引、CLIP 提示词和历史运行环境。当前权重文件本身的哈希未记录，不伪造。
- `protocol_fingerprint` 绑定配置；逐图 `score_version` 还绑定校准结果和代码哈希。修改其中任何部分后使用新输出目录；修改科学定义还必须增加协议版本。

## 参考标签与正确判定

参考类别先继承历史数据集标签。预测正确指固定候选集合中原始分数的 argmax 类别等于审核后的参考类别。完全相同的最大分数按历史类别顺序取首项。

标签审核输入为 UTF-8 CSV：`original_id,sha256,review_status,reference_class_id,reviewer,reviewer_kind,reviewed_at,evidence`。

| 审核状态 | 含义 | 评分处理 |
| --- | --- | --- |
| pending | 继承标签，尚未审核 | A/B 候选分数空；另存 `diagnostic_a_inherited`，只作未审核诊断 |
| confirmed | 审核同意原标签 | 数据与模型完整时可计算探索性 A；B 另需通过校准条件 |
| corrected | 有证据修正为候选集合内另一类别 | 按修正标签重新判定各模型正确性；历史输出保留 |
| uncertain | 遮挡、对象太小、类别或语义范围无法确认 | A、B 及未审核诊断均为空 |
| out_of_scope | 无可确认的受支持类别 | 全部评分为空 |
| exclude | 其他记录明确理由的排除 | 全部评分为空 |

审核接受必须有字节哈希、审核者、审核类型、时间和证据。`assistant_visual` 仅表示助手视觉检查，不冒充人工复核；研究报告继续保留人工复核不足的限制。
模型出错或模型一致本身都不是修改标签的证据。原图中目标清晰时可以记录图像内的类别描绘；玩具、仿制物或只有关联场景且语义边界不确定的，首轮保守记为 uncertain，留在开发问题清单中。
图中多对象不自动等于标签错误，但必须能明确识别所标目标。不能确定正确答案的图片不得被高难度解释吸收。

审核抽样：固定随机种子 20260907，每类从排序后的 ID 中抽 5 张；再加入所有模型出错、分歧或缺少输出的图片，以及数据问题图片。两种选择理由分别保留。定向审核样本的错误率不能作为总体错误率。

## 完整性与同源隔离

准备阶段检查唯一 ID、唯一路径、ZIP 成员、图片解码、类别顺序、预测索引、预测 argmax、历史正确标记、有限分数与完整向量。
缺失模型、重复预测、异常分数、类别不支持、原图标签冲突或原图无法定位都列入问题清单。评分模型输出有问题时整条 A/B 缺失，不改变分母；只缺少辅助验证模型时允许 A，但独立模型统计明确报告缺失数。

同 ID 和相同原图 SHA-256 使用并查集合并为 `source_group_id`。副本及现有蜕变图继承同源组。
`lineage.csv` 的蜕变条目只用于说明同源关系，不读取其预测来定义原图难度，也不执行变换、鲁棒性指标或蜕变测试。
相同原图字节的预测类别冲突时排除对应模型记录。给定任何用途划分，整个同源组（含尚未分配状态）必须一致。
近似重复和相同场景仍需后续审核；精确哈希不等于完成近似去重。

## 模型角色与来源证据

首轮探索性 A 的固定评分模型为 ResNet-50 与 Swin-T，分母为 2。二者支持当前类别、结构不同，但共享 ImageNet 训练来源风险。
CLIP ViT-B/32 仅作不参与评分的辅助验证模型；其预测不参与 A/B 公式、温度拟合或评分组合中的临时分母调整。
这不是永久正式模型组合，也不意味着 CLIP 与样本来源独立。

| 来源标记 | 证据边界 |
| --- | --- |
| known_training_overlap | 既有训练成员证据与当前图片 ID、历史和当前字节哈希吻合 |
| official_validation_verified_not_proof_of_unseen | 既有官方验证标签、ID 和字节核对吻合；仍不代表全程未见过 |
| unknown | 未找到充分成员证据；不得改写为无训练重合 |

CLIP 的逐图训练成员关系始终记录为未知。对于本轮数据，来源风险没有排除时，所有分析只能是探索性结果。
历史 GPU 输出缺乏逐图输入哈希：本轮核对归档大小并新建哈希链，不能事后证明历史推理字节身份。

## 数据用途与冻结

初始用途全为 `unassigned`。先报告审核可用数量、每类覆盖及各模型错误数，再决定是否有条件分配用途。本模块不按固定比例自动切分，也不根据错误率补样。

显式划分 CSV 为 `original_id,source_group_id,split`，必须完整覆盖基准集合。允许的用途：

- `calibration_fit`：只用于拟合各评分模型的温度。
- `calibration_check`：独立检查校准效果；与前者同属于用户方案中的校准部分。
- `development`：比较方法、诊断异常和确定规则。
- `validation`：冻结规则后才评价。开发输出不暴露此部分预测、正确性或分数。
- `unassigned`：未规划数据，只能作单独的探索性诊断，不冒充开发或验证集。

`freeze` 绑定准备结果、有效标签、完整划分、校准结果、配置、代码和开发产物的哈希。
`evaluate --frozen` 只能评价 validation，不接受新审核或新划分，不重新拟合温度。
冻结是工程约束，不能让已经查看过的历史预测变成真正盲测；也无法替代外部研究过程对重复使用验证集的管理。再次调规则须建立新版本，并披露原验证数据已被使用。

## A 与 B 的定义

对固定评分模型集合 M、审核后的参考类别 y：

```text
A(x) = sum(argmax(z_m(x)) != y for m in M) / len(M)
B(x) = 1 - mean(softmax(z_m(x) / T_m)[y] for m in M)
```

每个模型独立转为概率后取正确类别概率，再求均值。不能用最大类别概率替代，不能平均原始 logits，不能先平均 logits 再 softmax。A/B 分开保存，不加权合成。

温度使用 calibration_fit 上的多类负对数似然最小化；稳定 log-sum-exp 与对数温度的一维有界搜索保证数值可复算。每个模型一个正温度；不改变 argmax。

本轮操作性校准门槛：fit 和 check 各至少 100 个审核有效同源组、每类至少 5 个、每个评分模型各至少 5 个错误；温度范围 [0.05,20]，落在边界则拒绝。
calibration_check 的 NLL 和多类 Brier 均不得比温度 1 更差，同时记录固定十箱的最高类别置信度 ECE。门槛是预设工程防线，不是统计充分性定理，不能被解释为通过研究验收。
任一评分模型条件不满足，则整个 B 为待验证，正式逐图 B 留空。calibration_fit/check 本身不发布 B 评价分数。

## 验证与验收

所有方法分析按 unassigned、development 或冻结后的 validation 分开；不会把校准样本混入评价。

- 标签有效性：审核选择理由、结论、排除原因及失败样例逐图保存。
- 区分能力：不同分数数量、最大同分组、同分对占比；B 额外报告 A 同分组内的区分。小数更多不代表预测价值更好。
- 辅助验证模型：固定数值区间 [0,.25)、[.25,.5)、[.5,.75)、[.75,1] 中的组数、错误数、错误率及 95% Wilson 区间，并报告错误预测 AUC。区间只用于诊断，不是难度等级。
- 排序稳定性：逐一移除评分模型，报告平均秩的 Spearman 相关和名次变化；B 使用已固定的各模型温度。常量排序返回 null。
- 类别影响：每类重复上述分析，报告有定义类别的宏平均 AUC；没有正负样本的类别返回 null，并记录有效类别数。

精确同源组在独立模型错误率统计中只计一次。Wilson 区间假定不同原图组可视为独立观测；来源重合、场景相关、近似重复、类别不均与定向选样都限制这个解释。

工程检查覆盖对齐、完整性、A/B 独立复算、异常排除、同源和阶段隔离、历史文件前后哈希一致与拒绝覆盖。
研究结果独立保存为 `exploratory_only_not_ready_for_formal_grouping`。通过工程检查不会自动改变此状态。
只有未来有足够标签、校准、独立验证、稳定性和类别分析证据后，才能另行讨论正式协议与分组阈值。本轮不自动进入后续阶段。
