# 风险先行、覆盖检查与条件触发迭代：草图修订说明

本说明对应2026-10-21提出的流程修订草图，不表示已重新运行实验。图像通过本地 imagen CLI 调用 gpt-image-2，并参考用户上传的原总览图生成。

## 状态提取如何简化

将原图左侧的六个面板压缩为两个主要步骤：

1. 字典确定：LLM提出共享与类别专属字段，人工仅审查字段定义及取值，确定后固定。
2. 自动状态提取：原图、目标框及裁剪图提供证据，VLM逐字段提取，程序计算尺度，输出统一的目标状态记录。

字典内容在独立表格或附图展示。总览图不重复展示代表图片、完整字典、两次VLM图标和多组状态标签。

## 修订后的选样流程

1. 沿用固定五维等权风险评分：尺度、可见性、遮挡、截断、朝向。在类别内部排序并划分Q1—Q5，确定类别、风险层及必要的细分风险单元配额。
2. 在配额内选取部分目标构成初始集合S₀，保留后续补充名额。初始选样不以覆盖增益驱动；初始规模和选样随机种子需在正式实验前固定。
3. 按固定字典检查出现覆盖率与支持完成度。
4. 若两项覆盖指标均达到预设阈值，则按剩余风险配额完成选样；追加目标不会降低固定字典下这两项指标。最终集合重新核对覆盖与配额。
5. 若未达标且仍有名额和可行候选，才进入贪心补充：在配额允许的未选目标中选取覆盖边际增益最大的一例，更新状态支持和已用名额，再返回覆盖检查。
6. 若预算用尽或候选耗尽，停止补充；保留并报告未达到阈值的指标和状态，不能承诺必然达标。
7. 固定所选目标后输出覆盖报告，再以同层多类别集合计算类别F1和Macro-F1；分类器预测不参与选样。

## 两项检查指标

对类别c固定的非unknown状态字典U_c，记状态支持数为n_s：

- 出现覆盖率 C_occ = mean_s 1[n_s ≥ 1]。
- 支持完成度 C_sup = mean_s min(n_s/K, 1)，现有项目K=20。

图中将用户所说的“状态率”按原参考图的“支持完成度”表达。它不等于达到K例的状态比例 mean_s 1[n_s ≥ K]。后者可以另行报告，但不能与支持完成度混用。

覆盖阈值α、β及初始预算B₀尚未指定，不在草图中虚构百分比。候选池未出现的已声明状态仍保留在字典分母，因此100%覆盖可能不可达。是否采用逐类达标或跨类平均达标，也需要在实验协议中固定；逐类结果必须保留，避免平均值掩盖个别类别的不足。

## 与已有项目的区别

已有实现：风险配额约束下直接贪心选满预算，再报告覆盖和分类结果。

本次提出：先形成风险约束初始集合，再检查覆盖；覆盖不足时条件触发贪心补充，每次补充后重新检查，并保留预算终止出口。

本次只修订流程设计和草图，不修改已有实验结果。后续验证应保留同预算、同风险配额的随机选样与原直接贪心对照，报告覆盖、支持、贪心调用次数及最终阈值达标情况。
